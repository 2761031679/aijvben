## 1. 目标

用户原话转写：

> 服务器后端只负责**信息存储、接收命令、信息调用**。
> 服务器打包的前端只负责**沟通 AI、编辑命令发送到服务器、获取信息目录、组合信息目录、网页前端 UI 服务**。
> 新增一个**插件**：内容和前端一致，但没有 UI，给 AI 调用。
> 这样所有 AI 都能通过前端或插件调取服务器数据。

补充约束（用户在 D1–D6 里的答复）：

| 编号 | 结论 |
|---|---|
| D1 | 两边都要。插件给**主持人 AI** 用；玩家用插件只能「让 AI 调插件，那个 AI 成为主持人」。插件是**前端内置能力剥离出来**给平台外 AI 调用的。 |
| D2 | 网页端有**免费额度 / 免费活动**，用完后玩家自填 API Key。**插件不含任何 AI / API Key 调用代码**——插件只在「用户已经有 AI」的前提下生效，钱由用户自己出。 |
| D3 | AI 能看到**全部 approved 剧本**，看不到未过审的。权限归后端。 |
| D4 | AI 可上传 / 修改剧本；可投票 / 举报 / 关注，前提是用户允许。**站点没有评论功能**。 |
| D5 | 用户授权 AI 用自己的身份；匿名也能上，但只有游客权限（只能看游客能看的剧本）。 |
| D6 | 云存档玩家本地一份 + 账号云端一份，每玩家同时只有一份，以**时间最新**为准。订阅信息挂在玩家账号。AI 代表玩家账号，玩家能做的 AI 都能做（所以 AI 能影响趋势）。**实名信息彻底隔离，只有网页端能实名**。Godot 残留直接删。 |

### 2.2 五个查证结论（用户点名要查的）

#### ① 部署脚本为什么没同步 npc_configs

**答案：根本没有这条路径，不是「没写完全」。**

`deploy_to_server.bat` 只上传三样：

```bat
scp -r backend            → /opt/turtlesoup/
scp -r frontend           → /opt/turtlesoup/
scp   requirements.txt    → /opt/turtlesoup/
ssh  "cd /opt/turtlesoup && bash update.sh"     :: 只 pip install + systemctl restart
```

`npc_configs/` **一次都没有被上传过，也没有任何回传（pull）通道**。
线上提示词是通过管理面板保存接口**直接写在服务器磁盘上**的。所以流向是单向的：

```
本地 npc_configs ──(从未上传)──╳── 服务器 npc_configs
                                   ↑
                       管理面板直接写这里（唯一的真实源）
```

结论：**服务器上的 `npc_configs/` 才是权威源，本地是过期副本。**
`pull_db.sh` 只拉 `.db`，不拉 `npc_configs/`。

**顺带查出的 2 个脚本 bug（都不影响现网，但会让「重装」翻车）：**
- `migrate_server.sh:129` 写成 `systemctl enable turtulesoup`（**拼写错误**，enable 会失败，
  服务开机不自启；后面的 `restart` 也是同一个错名）。
- `migrate_server.sh:141-146` 验证段还在 `from backend.database import SessionLocal` /
  `from backend.models import Script`（重构前的扁平模块，早已不存在）→ 必然 ImportError。

#### ② 免费试用模式（D2 的地基，已经存在且完整）

三块站点设置键 + 一个专用端点：

| 键 | 结构 | 作用 |
|---|---|---|
| `free_ai_config` | `{provider, model, base_url, api_key}` | **站长自己的 key**。对外返回打码值，内部取明文 |
| `free_trial_config` | `{enabled, ip_limit:10, user_unlimited:true, user_limit:3, start_at, end_at}` | 活动开关 + 定时 + 游客按 IP 计次 / 登录按账号计次 |
| `free_trial_quota` | `{ips:{ip:count}, users:{uid:count}}` | 已用次数 |
| `free_trial_usage` | `{total_tokens, total_calls}` | 站长面板的成本可视 |

入口是免费对话接口——**服务端持有密钥、服务端直调上游、浏览器全程拿不到 key**，额度用完返回 429。

**这条正好印证 D2 的分工**：免费额度是**网页端特有的商业模式**，插件不参与。
插件不含任何 key，也不含任何 provider 调用。但**开房要扣额度，所以开房必须由玩家身份发起**（§5.1）。

#### ③ 权限系统现状（D3/D4/D5 的地基）

后端安全模块共 **5 个依赖（3 个守卫 + 2 个取用户）+ 2 个资源判断 + 3 个中间件**
（v1.1 这里写「3 个守卫 + 2 个资源判断」，与本文件 M13 的「5 个守卫」自相矛盾——评审 B4，按代码事实统一为 5 个依赖）：

| 现有判断 | 作用 |
|---|---|
| 管理员守卫 | 角色是 admin / owner |
| 管理员或站长守卫 | 角色是 admin / owner / station_master |
| 站长守卫 | 角色是 owner |
| 能否看完整剧本 | 作者 / `admin` / **`owner`** / （订阅 且 已通关） |
| 能否编辑剧本 | 作者 / `admin` / **`owner`** |

> ⚠️ **术语必须写角色字面量**（评审 B5）：上表第 2 行的「站长」= `station_master`，
> 而这两行的「站长」= `owner`。代码事实：`can_view_full_script` 只认 admin / owner / 作者 / (订阅且通关)，
> **`station_master` 没有任何特权**。文档里出现「站长」一律加角色名，不许只写中文。

**判定为「能用但不成体系」**：
- 没有能力抽象 → 每个路由各写各的角色判断（14 个路由里到处散落）
- 没有「未过审剧本」的统一门禁：**详情页 / 开体验 / 提问 / 提示 四个入口都只判了「未删除」，没判「是否过审」**
- **存在一条已上线的汤底越权路径**：NPC 取剧本内容的接口对海龟汤无条件返回汤底全套，游客亦可，
  且支持标题模糊匹配。详见契约 **§10.1**（评审 A1）。**这是本次审计最严重的发现，必须先于 P0 修**
- 「能否看完整剧本」把**汤底**和「订阅+通关」绑死 → **主持人 AI 天然拿不到汤底**，
  这是阻塞 1/2 之外的第 3 个坑
- 没有不变量测试，改一处权限不知道影响谁

→ 方案：收敛为 §4 的 M26（主体与能力），矩阵见契约 §10。

#### ④ 实名当前有没有实际作用 —— **确认：没有任何实际作用**

「已实名」这个字段全仓库只出现 10 处，**没有一处是权限门禁**：

| 位置 | 用途 |
|---|---|
| 建表 / 字段定义 | 4 处 |
| 认证成功时置真 | 1 处 |
| 塞进返回给前端的数据 | 1 处 |
| 用户主页显示一个徽章 | 1 处 |
| 注册成功后弹窗引导（可跳过） | 1 处 |
| 个人中心显示文字 | 1 处 |
| 前端轮询认证状态 | 1 处 |

**结论：实名状态是一个纯装饰字段。** 不实名：不限制上传、不限制体验、不影响等级/金币/成就、
不限制任何接口。用户说的「实名通道被堵死、扫完也没实际作用」**完全属实**。

实名链路本身实现是完整可用的（国家网络身份认证公共服务 · R01 扫码认证）：
生码 → 数字信封加密 + SM2 签名 → 扫码 → 原文字节级验签 → 置已实名 → 前端每 3 秒轮询最多 40 次。
**链路通，但通过之后什么也不发生。**

→ 方案：**按用户 D6 彻底隔离** —— 实名只在网页端、独立模块、不进插件能力集、
不进上下文包、不进任何 MCP 工具。M40 里把「注册后自动弹实名」改成纯手动按钮。

**一句话**：把「组合信息目录 + 状态机」从浏览器搬到 L2，前后端各留薄壳。
一份实现，两端消费，永不再漂移。

**依赖方向铁律（v1.2 重写，评审 A8 / B9）**：唯一权威是 **§9 依赖方向总图**。这里只记三条不可违反的：

1. **M21 不得调用 M22** —— 组装上下文不推进状态机。
2. **M23b 不得调用 M22** —— M23b 是纯执行器：只组上下文、发 turn、施加指令副作用；
   **它把执行结果作为返回值交给 M22，由 M22 推进相位**。
   > v1.1 让 M23b 调 M22、同时让 M22 调 M23b，绕出一个新环（评审 A8）。
   > **状态机的唯一所有者是 M22**，谁都不许旁路改 `phase`。
3. **M23a 不得调用 M23b** —— 认字是纯函数，不许顺手执行。

L2 内部合法调用链只有：

```
M25（路由） → M22（状态机/结算） → M21（组装） → M24（裁剪）/ M23a（认字）
                                └→ M23b（执行） → M11 / M02
```

## 5. 三条数据流（时序）

### 5.1 开房 + 取主持上下文（**v1.1 明确「谁开房」**）

```
① 玩家（网页点「开始体验」／或插件带玩家钥匙）
   POST /api/host/session/start { script_id, npc_id }
        │
        ├─ 主体 = 玩家（不是主持证！主持证不能开房，见契约 §10）
        ├─ 查并扣额度（免费活动 / 玩家自填 Key）
        ├─ 建会话，相位 = 主持中
        └─ 签发主持证 → { session_id, host_token, expires_at }
        │
② 玩家把 host_token 交给主持人 AI（插件自己收下，或复制粘贴给别的 AI）
        │
③ 主持人 AI：POST /api/host/context （带主持证）
        ├─ M21 组装：配方 → 提示词文件 → 剧本信息 → 线索面板 → 状态栏 → 玩家信息
        ├─ M24 裁剪：主持主体 → 保留 5 个主持专用字段
        └─ 返回 { system_prompt, prompt_hash, ... }
        │
④ 主持人 AI 把 system_prompt 原样塞进 role:"system"，用自己的模型开始主持
```

> **插件开 session 走不走免费额度？** 走。但**必须带玩家钥匙**，所以花的是**玩家自己的额度**，
> 不是站长的。这正是 D2「钱由用户自己出」的落地。没有玩家钥匙的纯第三方主持人不能开房。

### 5.2 一轮问答（标记解析搬到服务端）

```
① 主持人 AI 产出回复原文
        │
② POST /api/host/session/turn { session_id, reply_text }   （带主持证）
        │
        ├─ M23a 认字：正文 / 分段 / 指令清单（纯函数，不碰数据）
        ├─ M23b 执行：工具查询、改线索、推条件计数
        │     └─ 条件达阈值 → 相位 = 结算中
        ├─ M22 更新会话状态
        └─ 返回 { plain, segments, markers, phase, inventory,
                  settlement, ending_type, narrated, last_words_left }
        │
③ 前端 / 插件按结果渲染；若 phase = 结算中，准备接解说
```

### 5.3 结算（修掉「真相被截断」，v1.1 改超时机制）

```
① 条件达阈值
    ↓
② 相位 = 结算中（主持上下文**仍然有效**）
    ↓
③ **立刻落库（幂等）—— 按 ending_type 分支回落库顺序，见下**   ← v1.2 修正（评审 A6 / A7）
       ending_type = "win"  → 记通关 + 金币 / 经验 / 等级 + 解锁汤底
       ending_type = "lose" → **只记结局**，不记通关、不发奖励、不解锁汤底
    ↓
④ 服务端返回 settlement_pending，要求 await_narration = true
    ↓
⑤ 宿主 AI 继续在同一套主持上下文里把结局解说说完整
    ↓
⑥ 解说这一轮结束 → narrated = true
    ↓
⑦ POST /api/host/session/end { reason: "settled" }
    ↓
⑧ M22：主持证**降级为遗言证（不撤销）** → 相位 = 已结束
    ↓
⑨ 前端弹结算面板（含汤底原文 + 解锁徽章）
```

**旧实现的错**有两处：①「条件达阈值」之后**立刻**退出体验态，把主持上下文摘了（→ 真相被截断）；
②落库绑在解说之后（v1.1 引入）。新顺序写进契约 §7.3 / §7.3.1。

> **③ 为什么必须在 ⑤ 之前（A7）**：现网 `settlement.js` 注释就是「胜利先调通关接口落库，再展示面板，
> 玩家看到面板前数据已安全」。放在解说之后，主持人 AI 一卡住/断线，玩家赢了也不算数。
>
> **③ 为什么必须按 `ending_type` 分支（A6）**：现网 `showDefeat()` 明确「不标记通关、不解锁汤底、无奖励」。
> v1.1 的结算链没有任何分支，照它实现会把**失败结局当通关处理并解锁汤底**——明确的行为回退。

**超时不用固定秒数（v1.1 修正评审第 12 条）**：

| 机制 | 定法 |
|---|---|
| 安静超时 | 连续 **300 秒**没有任何请求才算超时。只要还在出字就不算 |
| 心跳续期 | 每次请求（含流式分片上报）刷新活跃时间 |
| 超时后 | 转已结束。**主持证不撤销**，降级为「遗言证」；**同时补做一次幂等落库**（若结局已达成未落库） |
| **遗言轮** | 凭遗言证可调用「一轮」**恰好一次**，服务端按体验配方返回上下文，**不重复记账、不重复落库**；调用后**立即撤销**（此后 410） |

> v1.1 一边写「超时后撤销主持证」一边写「凭旧主持证还能调一次」，同一张证不能既失效又可用（评审 A4）。
> **v1.2 统一：已结束不撤证，只降级为只许用一次的遗言证；用完即撤。撤销 = 从此 410。**

> 固定 60 秒的问题：解说本身就在那一轮的输出流里，流可能超过 60 秒，掐断等于又切半句。
> 遗言轮的目的就是**最坏情况也把话讲完**。
